# Internationalization (i18n)

## Locale policy

The default and fallback language is Korean (`ko`). Supported languages are `ko`, `en`, `ja`, and `zh-CN`. A previously saved supported locale in `dataToolkit.locale` takes precedence. Unsupported values fall back to `ko`; browser language is not used for automatic selection.

The initial HTML uses `lang="en"` as a static source-language declaration. The external runtime updates the document language to the selected locale. No inline script, style, or event attributes are required.

## Files and namespaces

`app/static/js/i18n/index.js` owns locale selection, persistence, DOM translation, interpolation, and fallback. `app/static/js/i18n/locales/{locale}.js` contains the locale catalogs. The catalog namespaces are `main`, `layout`, `files`, `history`, `navigation`, `preview`, `validation`, and `messages`.

All locales must contain identical namespace and translation keys. Keys must be stable identifiers, not display strings. Translate dynamic messages using `DataToolkitI18n.t(key, parameters)`, which replaces named placeholders such as `{count}` without interpreting HTML. Use `data-i18n` for static text, `data-i18n-aria-label` for accessible names, and `data-i18n-title` for titles. Render translated strings with `textContent` rather than `innerHTML`.

## Runtime behavior

`DataToolkitI18n.getLocale()` returns the current locale. `setLocale(locale)` validates and persists it, updates `document.documentElement.lang`, and emits `data-toolkit:locale-change`. `group(namespace)` provides the legacy per-language dictionary interface during migration. The main script still contains the existing feature handlers; no API endpoints or data processing behavior are changed.

## Verification

Run `python -m pytest -v`, `node --check app/static/js/app.js`, and inspect all four languages in the browser. Verify a fresh browser profile defaults to Korean, a saved locale persists after reload, the validation and job-history screens update, and CSP blocks no external script files. The static test validates catalog parity, default selection, and external script loading.

## Dynamic UI and selection controls

The upload status uses a semantic translation key. Language changes re-render its current known status rather than restoring a hard-coded English label. Theme choices, filter operators, sort direction, the Top label, history actions, and placeholder text use locale-specific display labels while preserving stable machine values. Language names remain native-language names; format identifiers remain unchanged. All user-facing translations use textContent or DOM properties and do not require inline scripts.

## Deployment cache invalidation

The home response uses `Cache-Control: no-cache, must-revalidate`. External CSS and JavaScript URLs receive a content-derived SHA-256 query version so updated translations and runtime logic are fetched after deployment. Restart the application process after deploying new Python files.
