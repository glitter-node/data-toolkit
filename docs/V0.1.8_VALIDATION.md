# v0.1.8 — Structural validation and detailed error reports

The Validate tab accepts optional required column names and a JSON schema. Existing `/api/validate` requests with `required` remain supported. `/api/validate/report` accepts the same file, `required`, and `schema`, plus `report_format=json|csv`, returning a downloadable report.

Schema example:

```json
{"allow_extra":false,"fields":{"id":{"type":"integer","required":true,"unique":true},"email":{"type":"email","required":true},"amount":{"type":"number","min":0},"status":{"type":"string","enum":["active","inactive"]}}}
```

Supported field types: string, integer, number, boolean, date (YYYY-MM-DD), datetime (ISO 8601), email. Supported constraints: required, nullable, unique, min_length, max_length, min, max, enum, pattern. `allow_extra` defaults to true.

Validation responses include `valid`, `columns`, `row_count`, `issues`, `issue_count`, `truncated`, `summary`, and `schema_fields`. Each issue includes row (CSV-like header offset: first data row is 2), column, code, severity, and message. The response retains at most 1,000 issue details while counting all issues. CSV reports contain the retained issue details, while JSON reports contain the full response summary. Input parsing and upload limits are inherited from v0.1.7. This is structural validation, not a replacement for domain-specific business rules.
